## What Was Built

**DB migrations (db/migrate.js):**
- `users.status` default changed from `'active'` to `'pending'` — new self-registered users land in pending state
- `users.max_group_users` — cap on how many group_users a Group Admin can invite
- `users.group_admin_id` — FK linking group_user to their Group Admin
- `users.permissions` — JSONB fine-grained permission flags for group_user
- `invitations.invited_role`, `invitations.group_admin_id` — invite scoping
- `products.group_admin_id` — group-level product ownership
- Data migrations: existing `user` role → `group_user` + `status='approved'`; existing `admin` → `status='approved'`
- Indexes: `users_status_idx`, `users_group_admin_id_idx`, `products_group_admin_id_idx`
- DB constraint: `group_user` must have `group_admin_id` (NOT VALID)

**middleware/auth.js:**
- `isApproved` — 403 if `req.user.status !== 'approved'`
- `isSuperAdmin` — role='admin' only
- `isGroupAdminOrAbove` — role='admin' or 'group_admin'
- `requirePermission(perm)` — factory returning middleware; passes admins unconditionally, checks `permissions[perm]` for group_user

**middleware/scopeGroup.js:**
- `scopeGroup` — attaches `req.groupAdminId`: null for SuperAdmin, self.id for GroupAdmin, parent's id for group_user
