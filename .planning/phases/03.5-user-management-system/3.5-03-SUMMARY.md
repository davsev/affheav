# Phase 3.5 Plan 03: Approval Flow, Group Management, and Invite Cap Summary

**One-liner:** Canonical middleware replaces local isAdmin; SuperAdmin approval flow, Group Admin-scoped member listing and permission management, member cap enforcement on invites, and group-aware user removal all wired into routes/users.js.

## What Was Built

**routes/users.js:**
- `isAdmin` local guard removed; all protected routes use `isSuperAdmin` or `isGroupAdminOrAbove` from `middleware/auth`
- `GET /pending` (SuperAdmin) — raw SQL query returning all `status='pending'` users ordered by `created_at`
- `POST /:id/approve` (SuperAdmin) — validates role, checks user exists and is not already approved, writes `status='approved'`, `role`, and optionally `max_group_users` via `updateUserById`
- `GET /group` (Group Admin) — returns own group members (`group_admin_id = req.user.id`); SuperAdmin gets all approved users
- `PUT /:id/permissions` (Group Admin) — sanitizes 7 boolean flags (`add_products`, `edit_products`, `delete_products`, `view_logs`, `trigger_send`, `manage_schedules`, `view_settings`), calls `updateUserById` with JSONB permissions, invalidates cache via `_cacheInvalidate`
- `POST /invites` (Group Admin / SuperAdmin) — Group Admin path checks current member count against `maxGroupUsers`; returns 403 with `limitReached: true`, `current`, and `max` fields when at cap; SuperAdmin path can invite `group_admin` or `group_user`
- `DELETE /:id` (Group Admin / SuperAdmin) — Group Admin restricted to own group; group_user removal has no product side effects; group_admin removal either transfers products to SuperAdmin (`keepProducts=true`) or bulk-deletes them
- `PUT /:id` updated: `validRoles` now includes `group_admin`, `group_user`; `validStatuses` includes `approved`, `pending`, `suspended`
