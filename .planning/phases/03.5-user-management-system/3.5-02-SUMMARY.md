# Phase 3.5 Plan 02: Registration Paths + OAuth Routing Summary

**One-liner:** Three-path registration (self/invite/bootstrap) with role and status assignment wired through userService, inviteService, and OAuth callback; pending users routed to Hebrew RTL waiting page.

## What Was Built

**services/userService.js:**
- `_row()` now maps `status` (default `'pending'`), `maxGroupUsers`, `groupAdminId`, `permissions` from DB columns
- `createUser()` accepts `role`, `status`, `groupAdminId` params; bootstrap admin check (ADMIN_GOOGLE_EMAIL) promotes to `admin`+`approved` overriding passed-in values
- `updateUserById()` expanded to allow `permissions` (JSONB cast), `group_admin_id`, `max_group_users` fields
- `_cacheInvalidate` exported for external cache invalidation after permission changes

**services/inviteService.js:**
- `createInvitation()` signature extended: `invitedRole` (default `'group_user'`), `groupAdminId` (default `null`)
- INSERT now writes `invited_role` and `group_admin_id` columns added in Plan 01

**server.js OAuth callback:**
- Self-registration path: no invite token → `role='group_admin'`, `status='pending'`
- Invite path: valid token → `role=inv.invited_role`, `status='approved'`, `groupAdminId=inv.group_admin_id`
- Bootstrap: handled inside `createUser()` via ADMIN_GOOGLE_EMAIL env var
- Removed `no_invite` gate — self-registrants are now allowed (pending approval)
- Suspended check: `status === 'suspended'` instead of `status !== 'active'`
- Post-login redirect: pending users → `/pending` instead of `/`
- `/pending` route: Hebrew RTL dark-theme waiting page with logout link

- **Fix:** Changed to `if (user.status === 'suspended')` — only explicitly suspended accounts are rejected.
