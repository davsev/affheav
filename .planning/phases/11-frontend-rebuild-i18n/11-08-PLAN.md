**Settings.tsx:**

Section 1 — General:
- Language switcher: two `Button` components (he/en) in a `ButtonGroup`. Active language has `variant="filled"`, inactive has `variant="outline"`. On click: call `useLangSwitch().switchLang(lang)`. Current lang from `useLangSwitch().currentLang`.
- WhatsApp Web JS panel: `GET /api/whatsapp/status` on mount. Status dot (green/red) + status text. Buttons: "Refresh" (`GET /api/whatsapp/status`), "Reset Session" (`POST /api/whatsapp/reset`), "Show QR" (toggle `Image` with QR from `GET /api/whatsapp/qr`). Groups list: `GET /api/whatsapp/groups` → render as `List` of group names.

Section 2 — Niches:
- Active niche: full credential form card for the `activeSubjectId` niche (from `useSubjects`). Load niche data via `GET /api/subjects/:id`.
- Form fields using `CredentialField` for sensitive values: WA group name (`TextInput`), join link (`TextInput dir="ltr"`), webhook URL (`CredentialField` — `connected: !!data.webhookUrl`), FB page ID (`TextInput dir="ltr"`), FB access token (`CredentialField`), FB app ID (`TextInput dir="ltr"`), FB app secret (`CredentialField`), IG business account ID (`TextInput dir="ltr"`), AI prompt textarea (`Textarea`).
- "Generate FB Token" button → opens `GenTokenModal`.
- Save button: `PATCH /api/subjects/:id` — only include `CredentialField` values that the user actually typed (non-empty value). Boolean-present fields should not overwrite server values if user left them blank.
- Other niches: collapsed `Accordion` with one panel per non-active subject (same credential form).
- New niche button: inline form toggle with name field + save (calls `POST /api/subjects`).

**Credentials.tsx (FE-04 — platform connection screens):**
Fetch user credentials status: `GET /api/users/me/credentials` — returns `{ facebook: boolean, instagram: boolean, aliexpress: boolean, whatsapp: boolean }`.

Four sections (one per platform) using Mantine `Paper` cards:

**Facebook:**
- `CredentialField` for page ID, access token, app ID, app secret (all `dir="ltr"`)
- `connected` prop from API boolean
- Save: `PATCH /api/users/me/credentials` body `{ facebook: { pageId, accessToken, appId, appSecret } }` — only include fields with non-empty values
- StatusBadge shows connected/disconnected

**Instagram:**
- `CredentialField` for IG business account ID, access token
- Save: `PATCH /api/users/me/credentials` body `{ instagram: { accountId, accessToken } }`

**AliExpress:**
- `CredentialField` for app key, app secret, tracking ID
- Save: `PATCH /api/users/me/credentials` body `{ aliexpress: { appKey, appSecret, trackingId } }`

**WhatsApp:**
- `CredentialField` for webhook URL, WA group name
- Save: `PATCH /api/users/me/credentials` body `{ whatsapp: { webhookUrl, groupName } }`

After save on any platform: re-fetch `GET /api/users/me/credentials` and update `connected` state.

**Users.tsx:**
Guard: render `null` (or redirect to dashboard) if `!isAdmin`. The App.tsx tab router already hides this nav item, but the page itself should also guard.

Section 1 — Registered Users:
- Fetch `GET /api/users` on mount (admin endpoint).
- Mantine `Table` with columns: avatar, name, email, role badge, status badge (active/suspended), actions.
- Actions per row:
  - Activate: `PATCH /api/users/:id { status: 'active' }` (if currently suspended)
  - Suspend: `PATCH /api/users/:id { status: 'suspended' }` (if currently active) — show confirmation via `modals.openConfirmModal`
  - Delete: `DELETE /api/users/:id` — show confirmation modal, disabled for own account

Section 2 — Active Invitations:
- Fetch `GET /api/users/invites` on mount.
- Table: email, created date, expiry, status, actions (revoke: `DELETE /api/users/invites/:token`).

Section 3 — Invite User:
- `TextInput type="email"` for email address.
- "Send Invite" button: `POST /api/users/invites { email }` → returns `{ inviteUrl }`. Display the invite URL in a `CopyButton` + `TextInput` (read-only, `dir="ltr"`) so admin can copy and share.

Admin Tools section:
- "Migrate Subjects from Google Sheets" button: `POST /api/users/admin/migrate-subjects`. Shows result notification.
- "Migrate Products from Google Sheets" button: `POST /api/users/admin/migrate-products`. Shows result notification.

**FeatureFlags.tsx:**
Guard: render `null` if `!isAdmin`.

Phase 5 flags API contract (implemented in Phase 05, plan 02 — `apps/gateway/src/routes/admin.ts`):
- `GET /api/flags` → `Flag[]` where `Flag = { name: string, description: string, enabled: boolean }`
- `PATCH /api/flags/:name` body `{ enabled: boolean }` → returns updated `Flag` (400/404/500 on error)

Fetch `GET /api/flags` on mount. Store as `flags: { name: string; description: string; enabled: boolean }[]`.

Render Mantine `Table` with columns: name, description, toggle (`Switch`).

Toggle behavior:
1. Optimistically flip the local `enabled` state for the toggled flag
2. Call `PATCH /api/flags/:name { enabled: !current }`
3. On API error: revert the optimistic update and show error notification via `notifications.show()`

Include a note badge at top of page: `t('featureFlagsWarning')` — add this key to both locale files: `"featureFlagsWarning": "שינוי דגלים ישפיע על ניתוב הבקשות בזמן אמת"` / `"Changing flags affects request routing immediately"`.

No polling needed — the toggle is intentional, not a background process.
